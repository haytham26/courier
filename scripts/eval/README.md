# The evaluation set builders and checkers

The sets themselves live in `packages/eval/`. The builder writes a set, the checker fails the
build when the set does not meet the floor. Both run in CI (`quality-gates.yml`).

| Script                      | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `build-voice-eval.mjs`      | Builds the text side of the voice set: the address bank (from the real LINZ data), the spoken scripts with their gold intent and slots, and the planned audio files. `node scripts/eval/build-voice-eval.mjs`.                                                                                                                                                                                                                                       |
| `build-heldout-streets.mjs` | Builds the committed held-out street split of the voice set: 20 % of the Canterbury streets, split by street (never by address), seeded (mulberry32, seed 20261108) and byte-identical on every run, into `packages/eval/voice/manifest/heldout_streets.json`. `node scripts/eval/build-heldout-streets.mjs [--linz-dir data/linz]`.                                                                                                                 |
| `fetch-open-voice-data.mjs` | Fetches the open data of the voice set (A3): the Common Voice CC0 clips filtered by accent metadata, the MUSAN CC-BY noise beds and the reference STT judge's model, into `data/voice/` (git-ignored) with per-clip sha256 checksums, and writes `packages/eval/voice/manifest/licence.csv`. Restartable; it scans the mirror row by row because the viewer has no server-side filter, so it is slow. `node scripts/eval/fetch-open-voice-data.mjs`. |
| `check-voice-eval.mjs`      | Checks the voice set: the counts, the gold intents, the tags, and the built utterances' file and checksum rows (>=500 built from open data). It also refuses a main manifest containing a held-out street and a held-out manifest containing a non-held-out street (the committed split `packages/eval/voice/manifest/heldout_streets.json`), naming the row. `node scripts/eval/check-voice-eval.mjs [--heldout]`.                                  |
| `build-scanner-eval.mjs`    | Builds the scanner set: the label manifest, the slices, the field catalogue and the licence ledger. `node scripts/eval/build-scanner-eval.mjs`.                                                                                                                                                                                                                                                                                                      |
| `build-routing-eval.mjs`    | Builds the routing set (BUG-280): the committed stop pool (a suburb-balanced subsample of the real LINZ Canterbury addresses fetched by `scripts/data/fetch-routing-pool.py`, with each area's depot and finish point), the ROAD MATRIX (every ordered pair, from Valhalla over the Geofabrik OpenStreetMap extract — the service is started and waited for, the queries are chunked, resumable, and never symmetrised because one-way streets are real), and the 144 instances: 30/80/150/250 stops x 6 variants x 6 seeds, seeded with mulberry32 so the same seed makes the same day. `node scripts/eval/build-routing-eval.mjs`. |
| `check-routing-eval.mjs`    | Checks the routing set (BUG-280): the set's shape, the DETERMINISM of every instance (each one re-derived from its seed and the committed pool, stop by stop), the matrix's licence record and unroutable-pair count, every committed result re-walked with the core's own rules (the arrival waits for the window, the break sits where the core put it), and the directive's targets: within 2% of the baseline on average and 5% at worst, 0 violations where a feasible plan exists, solve p95 <3s at 150 stops. `node scripts/eval/check-routing-eval.mjs`. |
| `check-scanner-eval.mjs`    | Checks the scanner set: the counts, the ground truth, the fields and the licence of every row. `node scripts/eval/check-scanner-eval.mjs`.                                                                                                                                                                                                                                                                                                           |

## The routing set

Built (BUG-280): `packages/eval/routing/README.md` is the set's own document — what it measures,
how the days were made, and the measured numbers. The runner is Python (`uv run --project
services/api --extra eval python scripts/eval/run-routing-eval.py`) because it drives the
production engine (`app.solver`/`app.routing`) and the baselines (PyVRP long-budget, OR-Tools);
the checker is zero-dependency node so CI needs neither the Python toolchain nor the matrix
engine. The instructions to rebuild the set end to end are in the set's README.
