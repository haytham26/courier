# The gates

Every script here fails the build when its check fails. They are the mechanical half of
`docs/plan/CONSTRAINTS.md`.

| Script                               | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `check-workflows.mjs`                | The workflow-file gate (BUG-067): no workflow carries a key GitHub does not accept at a job or a step — the root cause was `if-no-files-found` written at a step's own level instead of inside `with:`, which made GitHub refuse the whole workflow for 65 runs in a row, on every event, with no report of the line — and no workflow reads its dispatch inputs through a bare `inputs` context, which exists for a dispatch and a call only. `node scripts/ci/check-workflows.mjs [workflow-directory]` (the default is this repository's own `.github/workflows`, resolved from the module so the cwd does not matter). |
| `__tests__/check-workflows.test.mjs` | The BUG-067 root cause as a step key, the same name inside `with:` (where the upload action reads it), a key inside a `run:` block scalar (which is not YAML), an action input inside `with:`, a typoed `runs-on` at a job level, the bare `inputs` form, the `github.event.inputs` form, an `inputs` mention in a comment, the no-space form, a directory that does not exist, the real tree (so the gate cannot go vacuous) and the CLI exit codes CI runs.                                                                                                                                                              |
| `check-parity.mjs`                   | The registers tell the truth (audit B1): every PARITY row is `Have` with a PR or run link, `Better` with the same, or `Planned` with its task; `check-parity.mjs` on `docs/status/PARITY.md` refuses anything else, on every gate run. It is also where `moved to PARITY` comes from: the words a BUGS row may end with are the same vocabulary. With `--base <ref>` it also runs the reopen guard: a `fixed`/`closed` BUGS row turned back to `open` fails unless the row says "Reopened with ..." (step 0, 2026-11-02; wired into the floor job of quality-gates.yml). |
| `__tests__/check-parity.test.mjs`    | A `Have` row with no link fails, an unknown status word fails, a `Planned` row with no task fails, and the count it prints is the register's own. |
| `check-floor.mjs`                    | The floor guard: scans the lines the branch adds for a new suppression, a skipped test, an `any`, an empty catch or a stub. `node scripts/ci/check-floor.mjs [base-ref]`.                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `check-conflict-markers.mjs`         | The merge-marker gate: no `<<<<<<<`, `=======` or `>>>>>>>` line survives anywhere in the tracked tree (lockfiles, vendored code and binaries excluded). `node scripts/ci/check-conflict-markers.mjs`.                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `check-control-chars.mjs`            | The control-character gate: no BEL, VT or FF byte (an escaping pass once corrupted 31 word-initial letters into these) in any tracked text file. `node scripts/ci/check-control-chars.mjs`.                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `check-mojibake.mjs`                 | The mojibake gate: no tracked text file carries a UTF-8 sequence that was read as Windows-1252 and saved again — U+00C2 U+00A7 where a section sign belonged, and the em dashes, arrows, ellipses, check marks and middle dots of the same accident (this row spells it in code points on purpose: the gate would flag its own documentation otherwise). Two rules: the sequences only an OEM code page reverses, and a Windows-1252 reversal that lands on one typographic character. The reversal table is the gate's own, because Node's `latin1` encoding truncates U+20AC instead of mapping it to 0x80. `node scripts/ci/check-mojibake.mjs`.                                                                                                                                                                             |
| `check-coverage.mjs`                 | The coverage ratchet: reads the summaries the test runs produced and fails below the floors. `node scripts/ci/check-coverage.mjs`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `run-coverage.mjs`                   | Runs the coverage of the packages, the API and the voice service, then calls the gate. `node scripts/ci/run-coverage.mjs`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `check-audit.mjs`                    | The dependency audit: fails on any high or critical advisory that is not a documented build-time exception, and on an exception that carries no owner, no review date, or a review date already in the past (an acceptance is never permanent). Its evaluator is importable, so the tests need no registry. `node scripts/ci/check-audit.mjs`.                                                                                                                                                                                                                                                                             |
| `check-licenses.mjs`                 | The licence gate: fails when a forbidden licence (GPL, AGPL, SSPL, Commons Clause, CC-NC, FSL, BUSL) reaches the shipped app. `node scripts/ci/check-licenses.mjs` (with `--write` it regenerates `docs/product/LICENSES.md`).                                                                                                                                                                                                                                                                                                                                                                                             |
| `check-secrets.js`                   | Fails when a required environment variable is missing. It prints the names, never the values. `node scripts/ci/check-secrets.js`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `grep-banned.ps1`                    | Greps the tree for the banned items (the old libraries, the CSS variables, the wrong hooks). `powershell -ExecutionPolicy Bypass -File scripts/ci/grep-banned.ps1 [paths...]`.                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `review-gate.sh`                     | The review board: the five checks (correctness, security, performance, design, privacy) that run before a merge. `bash scripts/ci/review-gate.sh`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `backtest.mjs`                       | The 50x backtest of the three package suites: the flakiness number. It is not in a workflow yet. `node scripts/ci/backtest.mjs`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `check-store-readiness.mjs`          | The local copy of the StoreReady check (the release manager's copy of the CI gate). `node scripts/ci/check-store-readiness.mjs [--repo .] [--app apps/mobile] [--apk <file>] [--json <file>]`.                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `store-ready-summary.mjs`            | Renders the StoreReady report as a job summary. `node scripts/ci/store-ready-summary.mjs <report.json>`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `check-doc-links.mjs`                | The link gate: every relative link in the live documentation resolves (`docs/archive`, `docs/evidence` and `docs/log` are history and skipped). `node scripts/ci/check-doc-links.mjs`.                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| check-e2e-pins.mjs                | The E2E pins gate (BUG-065): every workflow that boots an Android emulator declares the same MAESTRO_VERSION, MAESTRO_SHA256 and EMULATOR_BUILD, passes emulator-build to the action, and keeps the pins shape (a cli-X.Y.Z tag, a 64-char sha256, digits). A workflow that boots no emulator at all also fails: the gate cannot go vacuous. ode scripts/ci/check-e2e-pins.mjs [workflow-directory]. |
| `check-deploy-rsync.mjs`               | The deploy's rsync gate (audit 3a, 2026-11-05): the deploy step's rsync names `infra`, `services` and `packages` WITHOUT trailing slashes and carries `--relative`, because a source with a trailing slash contributes its CONTENTS - the three folders landed flat in /opt/courier and `--delete` removed what was there, so the deploy's own `cd /opt/courier/infra` failed on a directory that never arrived. The gate also proves both command shapes against a scratch directory where rsync is installed (CI's ubuntu runner) and against a simulation of rsync's documented semantics where it is not, and it asserts that the deploy still cds the directory it sends. `node scripts/ci/check-deploy-rsync.mjs`. |
| `check-smoke-version.mjs`              | The deploy's version gate (audit 3b, 2026-11-05): `deploy.yml`'s remote `smoke.sh` invocation FORWARDS `APP_VERSION`, `infra/smoke.sh` DIES without it (a smoke test whose version check silently does not run reports green about a deployment it never identified) with `--no-version` as the only skip for a local run, and the version fetch of `/openapi.json` cannot fail quietly with `|| true` (which left an empty file and then named the wrong cause). `node scripts/ci/check-smoke-version.mjs`. |
| `check-deploy-secrets-inline.mjs`     | The deploy's secret-inline gate (audit 3c, 2026-11-05): the `Deploy to the host` step spells NO secret into a command line (a secret in an ssh argv is readable in the remote host's own process list, and one quoting mistake from a log), carries the smoke token and staging domain in the step's `env:`, and pipes them to the remote shell over stdin (`printf … | ssh … 'read -r domain && read -r token …'`), with the remote command single-quoted so the local shell cannot expand into it. The step's run block is parsed with `bash -n` where a working bash exists. `node scripts/ci/check-deploy-secrets-inline.mjs`. |
| `check-deploy-gate.mjs`                | The deploy's gate gate (audit 3d, 2026-11-05): `.github/workflows/deploy.yml` carries a `workflow_run` trigger that names BOTH required workflows (`CI` and `Quality gates`) and reacts to `[completed]`, keeps `workflow_dispatch` (a human may always ask) and the `push` trigger (the verify leg builds the local-VM stack on every push), runs the deploy job on the gates' conclusion rather than on the push, does not `needs: verify` (a job that exists only on the push event), checks out `github.event.workflow_run.head_sha` rather than the branch tip, and carries a gate step that reads BOTH conclusions from the API and requires them completed AND successful. `node scripts/ci/check-deploy-gate.mjs`. |
| `check-e2e-avd-restore-keys.mjs`       | The AVD restore rule (audit 3e, 2026-11-05): the emulator workflows that carry an AVD cache (`android-e2e.yml`, `android-e2e-health.yml`) cache a key that includes the pins fingerprint AND carry NO `restore-keys` prefix, because a prefix that stops short of the fingerprint restores an AVD built under a different Maestro version, emulator build, system-image revision or option set - BUG-068's tiny-device-profile failure, re-armed one line below the comment that explains fixing it. Only an EXACT key restores. `node scripts/ci/check-e2e-avd-restore-keys.mjs`. |
| `check-e2e-sysimg-pin.mjs`             | The system-image pin gate (audit 3f, 2026-11-05): `.github/workflows/android-e2e.yml` carries a `SYSIMG_REV_<api>` pin for every api-level the e2e matrix runs; the pins fingerprint READS that value through an indirect variable (so a pin change is a key change and a cache miss by construction); a pre-step installs the image with three attempts, wiping the image directory between them, and ASSERTS `Pkg.Revision` equals the pin; the image cache is keyed BY the revision; and the record step FAILS when the emulator-runner action moved the image under the pin (the fix is a pin bump in its own PR, not a number recorded and forgotten). Without this the emulator's bytes change whenever Google publishes a revision, with no commit. `node scripts/ci/check-e2e-sysimg-pin.mjs`. |
| `check-e2e-trigger-conditions.mjs`      | The emulator workflow's job-level filter (audit 3g, 2026-11-05): the `pull_request` trigger of `android-e2e.yml` carries NO `paths:` filter (a trigger-level filter keeps the whole workflow from existing, so its check names are never reported and a required check that is not reported blocks every PR forever); a `changes` job diffs the paths with a plain `git diff --name-only` step (no new action, so nothing to SHA-pin and nothing for the licence inventory), fetches the WHOLE history (a shallow clone's base sha is an unknown revision, and the diff then reads as "nothing changed"), and declares the `build`/`e2e`/`a1` outputs; and build/e2e/a1 each carry `if:` reading the changes job's outputs, with the legs gating on the build job's success and the build job covering the flow-only case (the legs download the APK it uploads, and an unchanged app restores it from the content-hash cache). `node scripts/ci/check-e2e-trigger-conditions.mjs`. |
| `check-e2e-retry-budget.mjs`           | The emulator workflow's retry budget (audit 3h, 2026-11-05): PLAYBOOK 17.1 says a re-run is not a diagnosis, so the budget is ONE - the `e2e` and `a1` jobs of `android-e2e.yml` carry a `The retry budget` step as their FIRST step that fails when `github.run_attempt > 2` (before booting an emulator) and, on attempt 2, writes the justification request into `$GITHUB_STEP_SUMMARY`. `node scripts/ci/check-e2e-retry-budget.mjs`. |
| `check-design-gate.mjs`                | The design-lab gate (release hygiene, 2026-11-06): the diagnostics (`app/design`, `app/compat.tsx`) must be provably out of a release build - `metro.config.js` blockLists both paths when neither `EXPO_PUBLIC_DESIGN_LAB` nor `EXPO_PUBLIC_E2E` is set (and the gate proves the blockList does NOT also match a product screen), `buildFlags.ts` inlines the same decision, `app/_layout.tsx` registers the design route only under it, and the gated files must exist (no vacuous pass). `node scripts/ci/check-design-gate.mjs [app-dir]`. |
| `__tests__/check-design-gate.test.mjs`  | The real app passes; a metro config with no blockList fails, one missing either diagnostic literal fails, one whose blockList also matches a product screen fails, one applied unconditionally fails; a buildFlags that ignores a flag fails; an unconditional route registration fails; a tree whose gated files are gone fails. |
| `__tests__/check-e2e-retry-budget.test.mjs` | The real workflow passes; a job with no budget fails and is named; a budget that is not the job's first step fails; one that does not read the run attempt fails; one that never fails fails the gate; one that does not write the job summary fails. |
| `__tests__/check-e2e-trigger-conditions.test.mjs` | The real workflow passes; a trigger that still carries the paths filter fails; a workflow with no changes job fails; a changes job that reaches for a third-party action instead of git fails; one with a shallow clone fails; a job with no `if:` fails and is named; a build that does not cover the flow-only case fails; a leg that does not gate on the build job's success fails. |
| `__tests__/check-e2e-sysimg-pin.test.mjs` | The real workflow passes; a workflow with no pin at all fails on every leg; a matrix api without its own pin fails; a fingerprint that ignores the pin fails; an install step without the wipe between attempts fails; a record step that only records fails. |
| `__tests__/check-e2e-avd-restore-keys.test.mjs` | The real workflows pass; a workflow with a restore-keys prefix fails and names the file; a key that drops the pins fingerprint fails; a workflow that boots no emulator (or is not in the tree) is not the gate's business; a health workflow with a restore-keys fails even when the e2e one is clean. |
| `__tests__/check-deploy-gate.test.mjs` | The real workflow passes; a deploy that still runs on the push to main fails; a trigger naming only one of the two gates fails; one reacting to `requested` rather than `completed` fails; a checkout pinned to the branch tip fails; a deploy that `needs: verify` fails; a workflow that dropped workflow_dispatch fails; a workflow with no deploy job fails loudly. |
| `check-semgrep-exclusions.mjs`         | The Semgrep-exclusions gate (audit 3d follow-up, BUG-226): every `--exclude-rule` in the sast job's scan command of `quality-gates.yml` must be a line in `.semgrepignore` under a numbered reason (`# N. ...`), `.semgrepignore` must carry numbered entries, and every W-id it cites must have a row in the exceptions table of `docs/plan/CONSTRAINTS.md`. An accepted finding with no written reason is a suppression by another name (the floor's no-suppressions check only sees inline Semgrep suppression comments). `node scripts/ci/check-semgrep-exclusions.mjs [repo-root]`. |
| `__tests__/check-semgrep-exclusions.test.mjs` | The real tree passes; an `--exclude-rule` with no `.semgrepignore` line fails; a missing `.semgrepignore` fails; a cited W-id with no CONSTRAINTS.md row fails; a scan with no `--exclude-rule` fails; a missing exceptions table fails. |
| `__tests__/check-deploy-secrets-inline.test.mjs` | The real workflow passes; the old shape (secrets spelled into the argv) fails and names the line; a deploy that keeps the env but spells a secret anyway fails; one that pipes without reading fails; a step env that drops the two secrets fails; a workflow with no deploy step at all fails loudly. |
| `__tests__/check-smoke-version.test.mjs` | The real tree passes; a deploy that does not forward the version fails; a smoke.sh that skips the version silently fails; one whose fetch can fail quietly fails; a workflow that never invokes smoke.sh at all fails. |
| `__tests__/check-deploy-rsync.test.mjs` | The trailing-slash shape fails and names the slash, a relative shape that names none of the three sources fails, a deploy that no longer cds the directory it sends fails, a workflow with no rsync at all fails, and the real workflow passes. |
| `check-emulator-gpu.mjs`             | The emulator-GL gate (BUG-053): every workflow step that boots an Android emulator sets `-gpu swiftshader_indirect`, a second `-gpu` fails, and an anchor the gate cannot read fails loudly. `node scripts/ci/check-emulator-gpu.mjs [workflow-directory]` (the default is this repository's own `.github/workflows`, resolved from the module so the cwd does not matter).                                                                                                                                                                                                                                                |
