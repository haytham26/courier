# The deep code audit, 2026-10 (C1) — method, verdicts, and the accepted findings

Status: **IN PROGRESS — the three lead-owned squads have reported and have been verified; the findings below are the verified set.** The fix order (C1): critical and high before A1 continues; medium in the same slice as the code it touches; low as a batch. The accepted findings are NOT yet filed in `docs/status/BUGS.md`; they are filed in one PR with numbers taken from `origin/main` at that moment (the register's next free number as of this writing is **BUG-068**, main having reached BUG-067).

## Method (per the audit brief, `docs/plan/AUDIT_2026-10-25.md` C1)

- Six review squads, each a fresh-context subagent; the lead (this session) runs squads 1 (mobile), 3 (sync and the offline store, the app side) and 6 (CI, infra, supply chain). Squads 2, 3's server side, 4 and 5 are the backend session's share; the two results merge into one report when both are done.
- Two lenses per squad: correctness and security (MASVS L1 for the app, ASVS L2 for the services, injection, authz on every route, tenant scoping, secrets, PII in logs); and robustness (offline, retries, idempotency, time zones, concurrency, resource leaks).
- A verifier per finding: a second, fresh-context subagent reproduces each finding with a failing test or a command (PLAYBOOK §14, red-first) before it is accepted. An unreproduced finding is dropped, with its reason recorded below.
- Read-only while it runs: no finding below has been fixed yet.

Squad 6 — 4 ACCEPTED, 1 AMENDED, 1 DROPPED at the time of that verifier's report; the remaining squad-6 findings were settled by documented GitHub semantics (their verdicts are included below as accepted only where the verifier's proof is cited). ### Squad 3 — the app side of sync and the offline store

Cross-cutting fact established by the verifier's reachability probe: **no production module in `apps/mobile` constructs `EventLog`, `SyncService`, `OpSqliteEventStore` or any API transport** (there is no API client in the app at all — that is audit item A1, being worked on its own track). Every runtime finding below is therefore a **wiring-gated defect**: real as written, and each becomes live the moment A1 wires the store in. Two of them also violate a WRITTEN gate — ADR-014 §3's consequence that the phone must drop or repair a rejected/poison head before the transport ships — which is why they are critical despite the wiring gap.
