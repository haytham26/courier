## BUG-067 — the map-pack workflow could not start, and BUG-064's guard took the blame

  seconds** with `This run likely failed because of a workflow file issue`: no jobs, no steps, no log,
  no annotation naming the line.
- **The line.** `if-no-files-found: error` sat at a **step's own level**, a sibling of `uses:` and
  `with:`. It is an **input of `actions/upload-artifact`**, so it belongs **inside `with:`**. An

  lane. Both fixed, with `scripts/ci/check-workflows.mjs` (13 tests) as the Quality-gates gate that
  fails on either.
- **Why it took a bisect, not a theory.** My first theory was the `inputs` context; it was shipped,
  the run still failed, and the bisect named the key. Both bisect commits are labelled in the
  branch's history, and the register's root cause is the truth rather than my first guess.

## A5's first slice — the staging stack, the two images, the deploy

- **The stack.** `infra/compose.staging.yml` — one replica of each service, a 172.29 network so both
  stacks can run on one host, and Caddy's own root CA for a domain a local VM cannot be challenged
  for. It is a complete file, not an override: compose's `depends_on` is a deep merge, so an override
  cannot drop the second replica the edge waits for.
- **The images.** `services/api/Dockerfile` and `services/auth/Dockerfile`. Both run as a **non-root
  user** (Semgrep's `missing-user`, ASVS V14). The API's dependencies come from the lock
  (`uv sync --frozen`) and the image carries no test, ops or load-test package.
- **The deploy.** `infra/deploy.sh` — the migrations (`packages/contracts/db/schema.sql` with
  `ON_ERROR_STOP=1`, after `up -d --wait postgres`), the state file the rollback reads, the swap, and
  `rollback` re-applying the recorded images. `infra/smoke.sh` drives a real round trip through the
  edge, and says which checks it skipped rather than faking a token.
- **The workflow.** `.github/workflows/deploy.yml` — a **verify** leg on every push that builds both
  images and brings the whole stack up on the runner, and a **deploy** leg over SSH that rolls back
  when the smoke test fails. Without the OCI host and key, the deploy leg names the secrets it is
  waiting for instead of doing nothing.
- **Three defects in the existing stack, fixed:** the compose file named `apps/api` and
  `../db/schema.sql`; the API's healthcheck asked for `/health/ready`, which this API does not serve
  (its contract carries `/healthz`); and the API's boot refused a POD store with no signing grant,
  which the compose files did not pass through.
- **Proved locally, on the founder's 3 GB VM:** both images build, the migrations apply, and the API
  container reaches `Healthy` with `Application startup complete` and the healthcheck's
  `GET /healthz 200`. Docker stopped and removed afterwards.
