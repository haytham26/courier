### The second attempt on the Locust leg — reverted, and the root fix (§19.1.2)

The iteration budget (attempt 1 on that leg) was pushed and **the run still failed at 76 requests
with `LOADTEST_ITERATIONS: 8` set**. All 50 users spawn; the rate at which their greenlets emit
requests is the runner's property (~3 req/s on a healthy CI runner → 141-197; 70-99 on a slow
one; 31 on a slow local box). Bounding the users' work cannot make the count deterministic — the
activation is the stochastic part — so the budget was reverted and the guard was made to measure
the property the count proxied for: every surface touched, a 201 claim on `POST /runs` (identity +
seeded shift + API together), and a floor of 10 as a backstop (0-13 vacuous vs 31-197 healthy).
`loadtests/vacuous_guard.py` holds the pure function (locust's import monkey-patches ssl, which
RecursionErrors a pytest session — hence the separate module), pinned by 8 red-first cases, and
proved end-to-end: the 76-request healthy shape now prints "SLOs met", a dead API and an unseeded
day (409s, no 201) still print the vacuous line. Gates: 494 passed, 1 skipped · ruff clean ·
mypy clean.
