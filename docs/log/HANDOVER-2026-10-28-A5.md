## The one item that is short of green, named precisely

**A5's auth migration is merged but not yet proven by a run.** What the deploy does today:
`infra/deploy.sh` runs the contract's schema (the API's tables) and then
`npx --yes auth migrate --yes --config src/migrate.config.ts` from `services/auth`.

The proof run (40553281308) got through the API's migration and the stack came up with a
**healthy API**, then stopped at the auth service with Better Auth's `Missing tables`.
The `npx` form was then fixed to run the CLI (run 40558288895), and that run's error is the
next session's five-minute job:

```
[#better-auth]: Couldn't read your auth config. Error: Cannot find module 'zod'
```

`npx` downloads the CLI into its own cache, and that process cannot resolve the config module's
imports (`zod`, `better-auth`) from the service's tree. Adding `@better-auth/cli` as a
devDependency fixes the resolution but every CLI version pins its own `better-auth` (1.4.21),
which adds a second, vulnerable copy and the **dependency-audit gate goes red** — that is why
the branch `fix/auth-migration-env` (#85) was not merged.

**The path that is left, and it is a short one.** Better Auth 1.7.10 (the workspace's own,
patched version) exports its migration from `better-auth/db/migration` — `getMigrations` and
`matchType` — and the service's `createDatabase` already builds a **Kysely** `PostgresDialect`,
which is the adapter `getMigrations` requires ("Only kysely adapter is supported for
migrations", which is what a local probe printed when the dialect was not passed). So:

1. `services/auth/src/migrate.config.ts` exports `{ options, database }` — the same
   `createAuth(loadConfig())` object, with `database` being the kysely dialect;
2. a small ESM runner imports `getMigrations` from `better-auth/db/migration`, passes those, and
   applies the returned statements with `pg` in one transaction;
3. `infra/deploy.sh apply` runs that runner (`node services/auth/migrate.mjs`) with the same
   environment it already exports (`BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `AUTH_DATABASE_URL`),
   and no CLI, no `npx`, and no second `better-auth`.

Then A5's done-when is one push run away: the stack reaches two healthy services, the smoke test
drives the seeded round trip, and the founder's APK points at staging once the OCI host, key and
domain exist (FOUNDER_TODO).
