Turn-by-turn is four separable pieces, and conflating them is the usual mistake: **(1) the instruction engine** (route → ordered manoeuvres + voice text: Valhalla / GraphHopper / OSRM); **(2) the client SDK** (the state machine that tracks progress, detects deviation and re-routes); **(3) the map UI** (camera, puck, manoeuvre banner); **(4) the voice** (TTS of the instruction). We own (3) via MapLibre and (4) via sherpa-onnx. We need (1) and (2) — and (3)'s **banner icons** turned out to be the actual left-hand-driving blocker (§3.1).

### 6-month star trend — method note (proxy, as V4 §12.3 permits)

The **star timeline** is not readable with the token in `.env.local`: `GET /repos/{o}/{r}/stargazers` returns **HTTP 403 "Resource not accessible by personal access token"** (re-verified 2026-10-21; GraphQL `stargazerCount` works but returns only the cumulative total). **Every "stars gained in 6 months" figure is therefore UNVERIFIED.** The proxy used throughout is the one §12.3 prescribes: **releases in the last 6 months · commits in the last 90 days · distinct human maintainers in 90 days** (bot/dependabot excluded), plus **npm / crates.io / PyPI downloads per month** where a registry exists.

## 6. Decision

1. **ADOPT Ferrostar's Rust core** (the crate, BSD-3) as the navigation state machine, driven by **our own
   self-hosted Valhalla** through the `valhalla.rs` adapter, with **GraphHopper** as the second adapter.
2. **Vendor the `react-native/` workspace** from the monorepo at a pinned commit until upstream publishes
   the three npm packages (issue **#961** — verified open, `react-native/package.json` is `"private": true`). Budget the UniFFI build into the Expo prebuild pipeline (`npx expo prebuild` + the `build-android.ps1` / `build-ios.sh` scripts that ship in the repo). **Re-evaluate monthly**; switch to the published packages if they appear. Add `react-native-svg` to the app — the Ferrostar maplibre UI needs it and we do not have it.
3. **The left-hand-driving answer (the founder's specific question):** do **not** wait for #991. The routing
   and the instruction text are already left-hand-correct in **Valhalla** (`driving_side` from the OSM tag → OSRM serializer → PR #1990) and **GraphHopper** (`NavigateResponseConverter`). #991 is about the **banner icon art set** and the public API's driving-side parameter. So: **we render the manoeuvre banner ourselves** (our own icon set, our own "keep left" wording), pass the driving side as an explicit parameter (`DrivingSide.left`) through our `RouteProvider` interface, and use **Organic Maps (Apache-2.0)** as the legal reference for how a left-hand country is presented. If we prefer a pre-built banner instead,
   the fallback is **`maplibre/maplibre-navigation-android`** (MIT, telemetry-free), which already models `driving_side` — at the cost of a TurboModule we must write and an Android-only scope.
4. **The voice layer is done**: sherpa-onnx 0.4.4 (already pinned) speaks the instruction offline;
   Ferrostar's `SpokenInstructionObserver` gives us the trigger and the audio-session control.
5. **Fallback:** `maplibre/maplibre-navigation-android` if the vendored Ferrostar path slips. **Do not build
   our own navigation state machine** — Ferrostar's Rust core already has deviation detection, simulation and property-based tests.
