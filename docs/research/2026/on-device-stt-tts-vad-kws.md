### The bar in one sentence
**Offline-first, on-device by default, plain NZ English, low battery drain, runs on a mid-range Android (target: Redmi Note 11 class, 4 GB RAM), and no audio leaves the phone unless the driver says so.** A candidate fails if it needs a licence key, a per-call fee, a non-commercial weight, a GPU, or a New-Architecture-incompatible binding.

### 6-month star trend — method note (proxy, as V4 §12.3 permits)
The star *timeline* is not readable with the token in `.env.local` (`GET /repos/{o}/{r}/stargazers` returns HTTP 403; GraphQL `stargazerCount` returns only the cumulative total). **Every "stars gained in 6 months" figure is UNVERIFIED.** The proxies used throughout are the ones §12.3 prescribes: **releases in the last 6 months · commits in the last 90 days · distinct human authors in 90 days · npm downloads in the last 30 days** (2026-09-19 → 2026-10-18).

### 3.1 `k2-fsa/sherpa-onnx` (C1) — our engine
**Code read** (2026-10-21): `k2-fsa.github.io/sherpa/onnx/kws/index.html` (open-vocabulary KWS), `…/kws/pretrained_models/index.html` (the KWS model list), `…/tts/pretrained_models/kokoro.html` (the RTF table), `…/omnilingual-asr/`, `…/qwen3-asr/`, `…/moonshine/`, `…/sense-voice/`, `…/funasr-nano/`, `…/FireRedAsr/` (the engine list), the `kws-models` / `tts-models` / `asr-models` release assets (real file sizes), and the release notes of **v1.13.8 (2026-09-10)**.

*Behaviour checked — KWS is open-vocabulary.* The keyword file is a plain text list: `▁HE LL O ▁WORLD :1.5 #0.35`, where `:boosting-score` keeps a path alive through the beam search and `#trigger-threshold` is the minimum acoustic probability. The model is "a tiny ASR" whose decoder is restricted to the keyword list, so **a bespoke wake phrase and NZ hotwords ship as a text file, with no retraining**. `sherpa-onnx-cli text2token` generates it (token types `cjkchar`/`bpe`/`fpinyin`/`ppinyin`/`phone+ppinyin`), so pinyin transliterations of te reo place names can ride the same file.

*Behaviour checked — the pretrained KWS catalogue.* Three official checkpoints: `sherpa-onnx-kws-zipformer-zh-en-3M-2025-12-20` (**32.1 MB**), `…-wenetspeech-3.3M-2024-01-01` and `…-gigaspeech-3.3M-2024-01-01` (**15.3 MB** mobile build). The docs publish the latency/accuracy trade-off: **chunk-8 = 160 ms, chunk-16 = 320 ms**. There is **no te reo / Arabic / Samoan / Tongan KWS checkpoint**.

*Behaviour checked — hallucinations on silence were a real defect.* v1.13.8 merged **PR #3923 "Fix Moonshine v2 hallucinating text on silent audio"**, **#3921** (FunASR-Nano), **#3924** (Cohere Transcribe) and **#3920** (Canary "empty transcript when the first decoded token is eos"). For a driving app that pushes every utterance to an LLM, hallucinated text is a false action, not a cosmetic bug.

*Behaviour checked — the VAD chunking contract.* Issue **#4046** (opened 2026-10-13, closed the same day) is the most actionable finding in this whole file for us: *"VoiceActivityDetector returns different segments for the same audio depending on how many samples are passed per `accept_waveform()` call. Only window-sized calls (512 samples for silero) give the right segments. With 0.1 s chunks the segments grow, with 1 s chunks the start of an utterance is cut, and passing a whole file in one call loses the speech."* The reporter also noted that `python-api-examples/vad-microphone.py` itself passes 0.1 s (1600 samples) per call. **Our streaming path must feed 512-sample windows** or our endpoints will be wrong — and the failure mode is silent, not a crash.

*Behaviour checked — memory on a mid-range phone.* Issue **#4056** (2026-10-16 → closed 2026-10-20): on a **Redmi Note 11 (4 GB RAM)**, the SenseVoice int8 model (239 MB file) used **570–730 MB RAM**, with an app peak of **708 MB (7 s audio) / 773 MB (48 s audio)**; the same model as Q8_0 GGUF (253 MB) under a ggml engine peaked at **354 MB / 446 MB**. Those are *his* numbers on *his* device, not our measurement — but they are the only real mid-range-Android memory figures in the public record for this stack, and they are 2.5× the file size on the ONNX path.

*2026 PRs (merged, from `GET /pulls?state=closed`):* **#4064 / #4062** (JNI strings and TTS for characters outside the BMP — emoji and CJK Ext-B in an address or a name), **#4049** ("Raise ValueError when `KeywordSpotter.create_stream()` cannot encode keywords" — the failure mode our wake-phrase loader must handle), **#4051** ("Fix ZipVoice heap overflow for short text at speed > 1"), **#4055** ("Remove espeak-ng and piper-phonemize from sherpa-onnx" — upstream removed the GPL phonemisers, which is the same licence decision we made), **#3928** (Kokoro v1.0 `em_santa` voice), **#3898 + #3933** (**Nabra-82M Arabic TTS converted to the Kokoro runtime and shipped int8 — 80.8 MB** — this closes the "Kokoro has no Arabic" gap the previous version of this file recorded), **#3910** (Intel NPU via OpenVINO), **#3935** (ONNX Runtime → v1.28.2), **#3912** (data race on a shared PRNG in the FunASR-Nano and Qwen3-ASR recognisers). **Closed unmerged:** **#4024** ("fix: align Parakeet TDT v3 and Ultra with current NeMo preprocessing", 2026-10-07) and **#4004** ("Fix kaldi-style fbank for online nemo_ctc models — WER 40 % → 11.6 % on Persian FastConformer CTC", 2026-09-29) — both are **real accuracy bugs that are still open**, and the second one is a reminder that sherpa's own WER can be badly wrong for a language we did not test.

*Other 2026 issues worth watching:* **#4057** (open) "Nabra Arabic INT8: Token-boundary Process Exit & Internal Syllable Dots Reaching Kokoro Tokenization" — an Arabic TTS defect on the exact voice we would ship; **#4042** (open) "Omnilingual ASR aborts on input shorter than 400 samples"; **#4065 / #4053** (licence clarifications, including "v1.13.8 Apple TTS XCFrameworks: license and corresponding-source inventory" — exactly ADR-004's ledger requirement); **#4067** (ARMv7 wheel metadata breaking the uv universal lock).

*Maintenance:* 100+ commits/90 d across **38 human authors** (the API page cap is 100, so the true number is higher), weekly releases, **568 open / 1 060 closed** issues, 409 opened in 2026 — a high-volume, well-triage project. Production users listed by sherpa itself: Sherpa Voice, SmartVoice, Speed of Sound, VoxSherpa TTS, MediaTek BreezeApp.

*Verdict:* **KEEP, and pin v1.13.8.** It is the only stack that covers all four functions in one Apache-2.0 binary, and the 2026 additions (Qwen3-ASR, Omnilingual-ASR, Nabra Arabic TTS, Moonshine, SenseVoice, FunASR-Nano) are exactly the multilingual direction D3 asks for. Two things we must do ourselves: **the KWS binding does not exist in our wrapper**, and **the VAD window contract is easy to get wrong**.

## 6. Decision

1. **The on-device engine stays `k2-fsa/sherpa-onnx`** (Apache-2.0), via our own `react-native-sherpa-onnx` binding — **but we pin the engine to v1.13.8**, not the v1.12.35 the wrapper currently vendors, and we open a PR to the wrapper to (a) bump the pinned release and (b) add a **keyword-spotting binding**, which does not exist today in the npm package.
2. **STT on device: sherpa-onnx streaming transducer first.** The candidate set is `streaming-zipformer-en-kroko-2025-08-06` (**55.9 MB**, fits our APK budget with VAD + KWS), with `whisper-tiny.en`/`base.en` and Moonshine as fallbacks, and **Qwen3-ASR (Apache-2.0, 30 languages) via sherpa** as the multilingual challenger. **No engine is adopted as the default until the §4 harness produces WER on our set.**
3. **TTS on device: Kokoro (Apache-2.0 weights)** for the English/NZ voice, shipped as a **downloadable voice pack** (int8 en = 100.8 MB, over the APK budget), with **KittenTTS nano int8 (25–30 MB)** as the small-pack alternative and **Nabra-82M Arabic int8 (80.8 MB)** for Arabic. **Pre-generate** the repetitive prompts (addresses, counts, "next stop") — the published RTF is > 1 on a Pi-class CPU.
4. **VAD: sherpa's bundled Silero VAD only** (629 KB / 208 KB int8). **Our streaming path must call `accept_waveform()` with 512-sample windows** (sherpa #4046) — this is a code requirement, not a preference. We do not add the standalone Python/Java package.
5. **KWS: sherpa's open-vocabulary keyword spotting**, exposed through a binding we own. The wake phrase ships as a **text keyword file** (`▁HEY ▁COURIER :1.5 #0.35`) — no retraining — and the operating point is tuned with the **sensitivity sweep tooling** pattern from `react-native-voice-activator` against our own ≥ 8 h negative van corpus, because **sherpa publishes no false-accept rate** for this path. If the open-vocabulary path cannot hold ≤ 1 FA/hour on NZ audio, we train a **"Hey Courier" model with `heed-wakeword`** (Apache-2.0, models we own) and host it through the same RN wake-word package (TFLite/ONNX), never shipping openWakeWord's NC models.
6. **End-of-turn: evaluate `smart-turn` v3 (BSD-2) on the server/PC path first**; keep the on-device VAD as the fallback.
7. **Server side: `Qwen3-ASR` / `Qwen3-TTS` (Apache-2.0 weights)** — the licence-safe path ADR-004 already names; `Parakeet TDT` (CC-BY-4.0) as the measured fallback; `faster-whisper` (MIT) for a cheap Whisper path.
8. **OmniVoice stays out of the shipped product** (CC-BY-NC weights + Boson community licence). ADR-004 is unchanged. **ADR proposal to the CEO** (not a decision change): add an explicit ledger entry format for founder-licensed derived models, and keep the engine behind the swappable interface ADR-004 already requires.
9. **Never ship:** openWakeWord's bundled models (CC-BY-NC-SA), F5-TTS weights (CC-BY-NC), piper1-gpl and espeak-ng (GPL-3.0), Coqui TTS (MPL-2.0, not allow-listed), fish-speech (community licence), ten-vad (Agora field-of-use), Porcupine/Cheetah (proprietary, key-gated).
10. **The licence ledger becomes a shipped surface** (ADR-004 §4): the build reports the licence of the code **and** of the weights for every engine it can load, a non-commercial or unknown weight makes that engine unavailable **with the reason**, and the CI gate fails on a non-commercial weight present in the tree. `docs/product/LICENSES.md` still lists every dependency as `licence = unknown` — that table must be regenerated before any release.

## 7. Risks and fallbacks

| Risk | Impact | Mitigation / fallback |
|---|---|---|
| **No eval set** → every performance claim is a vendor claim | we cannot choose an engine on evidence | build the 200-utterance set in §4.1 **now**, inside the `EVAL.md` contract, before any adoption PR |
| **Our wrapper has no KWS binding** and pins a 5-month-old engine | the wake word cannot ship; we miss upstream fixes | fork/fork-friendly wrapper; PR to add KWS + bump to v1.13.8; contract test against the sherpa C API so the binding is swappable (sherpa-ncnn is the Plan-B runtime) |
| **VAD window contract (#4046)** | wrong endpoints, silent failure | feed 512-sample windows; add a harness assertion that a fixed clip always yields the same segments |
| **Hallucination on silence (#3921/#3923/#3924/#3920)** | false actions during a silent van | VAD-gated decoding; a `chatter` + `nonspeech` slice with a **≤ 1 % false-action rate** gate (M9) |
| **Memory: 2.5× file size on the ONNX path (#4056)** | OOM on a 4 GB phone mid-shift | prefer int8; measure RAM in the harness; consider the GGUF/ggml path if sherpa's ONNX footprint stays high |
| **Kokoro pack = 100.8 MB > 80 MB APK budget** | cannot bundle | downloadable voice pack; KittenTTS nano int8 for the small pack; pre-generated audio for repetitive prompts |
| **KWS accuracy is unmeasured everywhere** | we ship a wake word that false-fires in a van | our own ≥ 8 h negative corpus; the sensitivity-sweep tooling pattern; the wake phrase file is a config, so it can be changed without a release |
| **Silero VAD licence contradiction** | a licence defect on the shipped VAD weight | use sherpa's Apache-2.0 distribution, and get written confirmation from Silero before we cite Silero by name (ADR-004 risk table) |
| **Arabic TTS defect on Nabra (#4057)** | broken Arabic replies | the failure is loud (token-boundary process exit), not silent; Arabic pack stays behind a flag until measured |
| **`expo-speech` fallback depends on the device's TTS engine** | inconsistent voice, possible silence offline | treat as degraded mode only; the offline path must be the on-device pack |
| **Two native speech stacks (sherpa + ExecuTorch)** | APK size, maintenance, licence surface | one engine only; ExecuTorch stays a benchmark opponent until the eval set says otherwise |
