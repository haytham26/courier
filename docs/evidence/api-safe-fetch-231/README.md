# BUG-231 evidence - the shared `safe_fetch()` SSRF guard (audit item 4c)

## The gap
Every server-side fetch was a bare httpx call: `app/auth/jwks.py::_refresh` (`client.get(auth_jwks_url)`) and `app/agents/omniroute.py::_chat` (`client.post(base_url + '/v1/chat/completions')`). A URL pointing at a private/loopback/link-local address (or a redirect to one, followed inside httpx) would have made the API a proxy into its own network. Research: `docs/research/2026/security-hardening.md` row 61 and section 2 (no maintained Python SSRF library - PwnSSRF dead 2021, safeurl-python archived 2024 - so the guard is ours).

## Red first
`services/api/tests/test_safe_fetch.py` written before the implementation: collection error `ModuleNotFoundError: No module named 'app.safe_fetch'`.

## Green after
- `app/safe_fetch.py`: `check_url()` refuses non-http(s) schemes, hostless URLs, unresolvable hosts, and any host resolving to a non-public address - private, loopback, link-local, reserved, multicast, unspecified (`ipaddress` predicates); IP literals are checked WITHOUT DNS; one private record among public ones is refused. `safe_fetch(client, method, url, *, allowed_hosts=frozenset(), max_redirects=5, **kwargs)` sends `follow_redirects=False` and loops with `urljoin`, re-checking every redirect target. `UnsafeFetchError` subclasses `Exception` directly (not `ValueError`) so the jwks/omniroute wrappers never flatten a refusal.
- Wired: `jwks.py::_refresh` -> `safe_fetch(..., allowed_hosts=settings.internal_hosts | LOOPBACK_HOSTS)`; `omniroute.py::_chat` -> `safe_fetch(..., allowed_hosts=settings.internal_hosts)` with the new `OmniRouteSettings.omniroute_internal_hosts` (`OMNIROUTE_INTERNAL_HOSTS`). Operator-listed hosts are the single deliberate exception (BUG-131's compose `auth`; the self-hosted gateway).
- `tests/conftest.py`: autouse fixture fakes `app.safe_fetch._resolve` for the whole suite - host names -> `93.184.216.34`, `localhost` -> `127.0.0.1`, IP literals -> themselves - so the mock-transport tests stay hermetic while the guard's refusals of loopback/private literals stay real.
- `tests/test_safe_fetch.py` 12/12: scheme/hostless refusal; 8 non-public literals refused without DNS; private-resolving host refused; public host allowed; one-private-among-public refused; unresolvable refused; operator-listed host allowed (and a different host refused); redirect to `169.254.169.254` refused BEFORE the second request is sent; redirect to a public host followed; redirect loop refused at `max_redirects`; the JWKS refresh refused on a private resolve; the JWKS internal host (`auth`) still verifies a signed token; the OmniRoute private base URL refused and the refusal is an `UnsafeFetchError`, not an `OmniRouteError`.
