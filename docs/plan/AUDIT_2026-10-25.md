# Audit 2026-10-25: what stands between the repo and a real trial (binding; MASTER §21)

The founder's chief adviser read the repo on main at `c98475c` against MASTER_EXECUTION §6 (the Definition of Done), CONSTRAINTS and the registers. Each finding below names its evidence, so anyone can re-check it, and its done-when, so nobody can close it with words.

**The headline.** The screens and the services are strong, but they are not connected to each other. The app the founder would install today shows mock data; it does not speak to the API, it does not sync, and on-device voice is not wired. Every green E2E run proves the screens on mocks. That is the gap between "the CI is green" and "a courier can work a shift", and it comes before any new feature.

## P0: blocks a real trial (do these before any new feature)

### A1. The app is not connected to the server
- **Evidence:**
  - `apps/mobile/app/(tabs)/index.tsx` imports `mockStops` from `src/maps/stops.ts`.
  - There is no HTTP client for the runs, stops or `events:batch` endpoints anywhere in `apps/mobile` (a search for `/runs`, `/shifts` and `events:batch` finds only `src/sync/opSqliteEventStore.ts`, which is the local store).
  - `@courier/shared` (the contract schemas) is not a dependency of the app.
- **Do:**
  - Generate a typed API client from the contract (`packages/shared` and the OpenAPI the drift guard pins).
  - Sign in through Better Auth and attach the JWT.
  - Load the run and its stops from the API, and cache them in op-sqlite.
  - Send delivery events through an outbox: retry with backoff, idempotent ids, and the D41 conflict answers shown to the courier.
  - Every screen reads from one run store, never from `mockStops`.
- **Owners:** the backend owns the contract and a seed endpoint for a demo run; the lead owns the app side.
- **Done when:**
  - A CI E2E job starts the API and Postgres (docker compose) and runs the core flow (sign in, load the run, deliver 3 stops, go offline, deliver 1, reconnect, sync) against the real API with no mock.
  - The rows land in Postgres, asserted by the job.

### A2. On-device voice is not wired
- **Evidence:**
  - `src/voice/VoiceService.ts` needs `sttModelPath` and `ttsModelPath`, but nothing in the app passes them.
  - No model files are shipped (`apps/mobile/assets` holds icons and `maps` only), and there is no model download.
- **Do:**
  - Deliver the sherpa-onnx STT, the Kokoro TTS and the Smart Turn models: download on first run over Wi-Fi with a SHA-256 check and a resumable download, stored in app storage, with the size shown to the courier.
  - Wire `VoiceService` into `useCourierVoice`.
  - Define the fallback when the models are missing (the server path through OmniRoute, D25).
- **Done when:** on the release APK, on the emulator, a recorded utterance file played into the STT gives the expected transcript, the latency from the end of speech to the first audio is measured and recorded, and the missing-model path is tested.

### A3. The voice eval set is planned, not recorded
- **Evidence:** `packages/eval/voice/manifest/utterances.jsonl` has 840 rows, all `"status":"planned"`, and 0 recorded.
- **Do:**
  - Write the recording protocol and a small recording tool, and record the en-NZ slices, including in-van noise beds.
  - Speakers come from the founder's network: the recording is a FOUNDER_TODO, the tool and the protocol are ours.
  - Until then, run the eval on synthetic noise mixed into the clean slice, and say so.
- **Done when:** at least 500 utterances are recorded, and the word error rate and intent accuracy for each slice are in `packages/eval/voice/results/` with the command that produced them.

### A4. Mock data must never reach a release build
- **Evidence:**
  - `readerForThisBuild()` and the run content choose mocks by `EXPO_PUBLIC_E2E`.
  - Once A1 lands, nothing stops a mock import from staying on a screen.
- **Do:** add a build check that fails the release build if `mockStops`, `createMockLabelReader` or `src/design*/content.ts` are reachable from a non-E2E entry.
- **Done when:** the check runs in CI and a deliberate mock import makes it red.

### A5. No staging server
- **Evidence:** `infra/compose.prod.yml`, `backup.sh` and the restore drill exist, but there is no deploy job and no running environment.
- **Do:**
  - Add a deploy workflow to the Oracle host: compose, Caddy TLS, the migrations, a smoke test after the deploy, and a rollback to the previous image.
  - Add the monitoring from `infra/monitoring`.
  - Deploy OmniRoute's production config there (D25).
- **Founder input:** the OCI host and key (FOUNDER_TODO). Build and test the workflow against a local VM until then.
- **Done when:** a push to main deploys to staging, the smoke test passes, and the founder's APK points to staging.

### A6. No real-device path
- **Evidence:**
  - Every E2E run is on an emulator.
  - The BUG-061 real-device check is open.
  - BUG-033 (the acceptance script) is open.
- **Do:**
  - Write `docs/operations/ACCEPTANCE_TEST.md`: a 30-minute script the founder runs on a phone. It covers sign in, load the run, scan, voice, drive, deliver, the offline stretch, sync and the summary, with expected results.
  - Make the release APK of every merge to main downloadable from one stable link.
- **Done when:** the script exists and the founder's first pass is recorded in FOUNDER_TODO.

## P1: needed before the beta

### B1. The registers do not tell the truth
- **Evidence:**
  - `docs/status/PARITY.md` has 0 rows marked `Have`, 41 marked `Better` and 290 marked `Planned`, although screens, POD storage, sync and the solver have shipped.
  - `docs/status/BUGS.md` has 36 rows that are not closed. BUG-002 to BUG-033 are a feature backlog from before the monorepo, and several are at least partly done (BUG-012 sync, BUG-016 the solver, BUG-027 POD, with its server storage merged in #31).
  - MASTER §6 measures "done" from PARITY, so today "what is left" cannot be measured.
- **Do:**
  - Reconcile in one pass, one PR per register.
  - Every PARITY row gets `Have` with the PR link, or stays `Planned` with its task.
  - Every BUGS row that is a feature moves to PARITY or to the plan, and is closed in BUGS with the pointer. BUGS keeps defects only.
- **Done when:** a script counts the statuses and the counts match the merged PRs. The count goes into `docs/status/PROGRESS.md` and is updated with every merge.

- **Done when:** a search for `design2` in `apps/mobile` finds nothing and the APK size change is recorded.

### B3. The security backlog
- **Evidence:** BUG-059 lists the WebSocket token in the query string (`auth/websocket.py`), `/v1/engines` and `/v1/licences` unauthenticated, and `response_model` missing on 11 handlers.
- **Do:**
  - Move the token to the first WebSocket message or the `Sec-WebSocket-Protocol` header.
  - Authenticate or rate-limit the probes.
  - Add `response_model` everywhere.
  - Run an OWASP MASVS L1 self-review of the app before the beta.
- **Done when:** BUG-059 is closed with tests, and the MASVS checklist with its evidence is in `docs/security/`.
