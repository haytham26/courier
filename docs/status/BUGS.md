# Bug Tracker - Courier Copilot

> Every known bug is logged here. No bug is closed without passing the 50x backtest for its critical path.
>
> **The status words** (checked by `scripts/ci/check-parity.mjs`): `open` (a live defect) ·
> `doing` (the fix is in flight) · `testing` (the fix is on a branch, waiting on its run) ·
> `fixed` (the defect was fixed, with the PR) · `closed` (nothing to fix: the row was a feature
> request or a pre-monorepo layout complaint, and it now lives in the plan with its pointer) ·
> `moved to PARITY` (the row was a feature, not a defect: it is now a PARITY row with its task).
>
> **The reopen rule** (step 0, 2026-11-02): a row that goes from `fixed`/`closed` back to
> `open` must say why in the row — write "Reopened with <reason>" (the BUG-132/BUG-137
> convention). `scripts/ci/check-parity.mjs --base <ref>` fails the PR otherwise, because a
> register edited against a stale main is how BUG-074 was reopened twice.
>
> Reconciled 2026-10-26 by audit item B1 (PR #58): BUG-002 to BUG-033 were the pre-monorepo
> feature backlog, so each one now carries the pointer to the PARITY row or the plan item that
> owns it. The rows stay for history; the tracker keeps the defects from BUG-034 on and
> everything the sessions filed.

## BUG-061: the root cause, the two experiments, and what is still open (2026-10-25)

`GuardedPoolAllocator::deallocate` - a double or invalid free in how the sphere uses
Skia - so it is NOT only the emulator's GL and it can hit real devices. Following the
