## Deep review - top 5

1. **mobile-dev-inc/Maestro** (16,138 *, Apache-2.0) - YAML flows, a CLI orchestrator, platform drivers (Android driver APKs, an iOS simulator server) and a workspace concept. The last 20 commits (2026-10-05 to 2026-10-16) are **exactly our CI problems**: a fix that stops `assertScreenshot` crashing workspace validation (**Maestro has a native `assertScreenshot`**), a bounded emulator boot-wait so `start-device` cannot hang forever, typing that does not wait for window animations, and Android driver APKs versioned with the CLI. 333 open issues; 0 advisories. **Verdict ADOPT / KEEP - use `assertScreenshot` for the design gate (day/night, small/large, 200 % text); that removes the need for a hosted visual-regression vendor and keeps driver screenshots inside our CI. Pin the CLI to the `cli-2.11.0` release (the npm `maestro@2.1.1` package is a legacy channel).**
2. **expo/expo + expo-updates** (52,869 *, MIT, `expo@58.0.16`, `expo-updates@58.0.17`) - the OTA runtime checks a manifest on launch, downloads a new bundle, verifies it with a code-signing certificate and swaps it in; **channels** decide which manifest a device sees and `expo/fingerprint` identifies the binary for differential updates. Recent commits include a note that workflow update jobs cannot publish to protected channels (2026-10-19) - a real OTA-safety rule - and a cold-start-relevant iOS JS-object allocation fix. 2,161 commits/90 d, 33 human maintainers, 0 advisories. **The OTA risk is ours, not the library's:** a bad JS bundle reaches every driver, so we require signed updates, **two channels only** (`production`, `preview`), a runtime flag per release and an immediate rollback path. The reference OTA server has had no commits since 2025-11-05 - **do not self-host yet**. **Verdict ADOPT.**
3. **microsoft/playwright** (98,129 *, Apache-2.0, `@playwright/test@1.64.1`) - a browser-automation server per browser, a test runner with projects/fixtures/trace artefacts and a first-class **trace viewer** that records the DOM, network and console for a failure. **We can run Lighthouse CI against a Playwright-started server**, so the Lighthouse >= 95 gate becomes a normal Playwright project rather than a separate script. 699 commits/90 d, 7 maintainers, v1.64.1 on 2026-10-14, 0 advisories. Risks: browser downloads in CI (use the official container image) and a heavy dependency for a small web app. **Verdict ADOPT for the dashboard E2E and the Lighthouse job; not for mobile (Maestro owns that).**
4. **getsentry/sentry-react-native** (1,824 *, MIT, `8.31.0`) - native iOS/Android SDKs plus a JS layer: JS errors, native crashes, ANRs, opt-in session replay and performance traces; sourcemap upload is handled by the Expo plugin. The last 20 commits include an update of the Expo sample to SDK 58 (2026-10-20) and a bump of the E2E tests to React Native 0.88.0 (2026-10-19) - **Expo SDK 58 / RN 0.88 verified today**. Security: one **low** advisory, GHSA-68c2-4mpx-qh95 (potential leakage of Sentry auth tokens by the RN SDK with the Expo plugin), patched in >= 5.19.1; we are on 8.31.0, so it is fixed, but the plugin must be configured with a **public DSN only** and no auth token in the client. **Verdict ADOPT for mobile errors, pointing the same SDK at GlitchTip so driver data stays in-house.**
5. **argos-ci/argos** (643 *, MIT) - a self-hostable service that ingests builds, diffs images and presents a review UI; 764 commits/90 d, 2 maintainers, but **no GitHub releases published** (tags only), so version pinning is awkward. **The decisive point is security:** the repo carries a **critical** advisory, GHSA-jw2w-wr3r-jp8w - "Anonymous cross-tenant build injection + GitHub status spoof via forged tokenless-github bearer", patched at commit `9cd9955`. For a product that screenshots a courier's screen with customer names, addresses and prices on it, that flaw in the tool which stores those screenshots is disqualifying until it is independently confirmed fixed and we are self-hosting it. **Verdict WATCH, do not adopt - use Maestro `assertScreenshot` + `reg-cli` instead.**

**Auth deep review.** **Better Auth KEEP** - a self-contained TypeScript service with a plugin system (organization, teams, expo, jwt+jwks, passkey, two-factor, stripe); 31 maintainers/90 d, 12 releases/12 m, 7.8 M npm downloads/week, 881 open issues; our `organization` + `expo` + `jwt` wiring is idiomatic and `services/api/app/auth/jwks.py` is a correct ES256/JWKS resource-server implementation with **no shared secret**, but the 1.7 migration checklist is a required ticket and the advisory velocity is a permanent obligation. **Kratos WATCH** (best identity engine, but no organisation + team model) - **Logto WATCH** (best multi-tenant console; MPL-2.0) - **Casdoor WATCH** (borrow the tenant-scoping of client requests) - **Lucia REJECT** (deprecated).

**Location deep review.** **expo-location + expo-task-manager ADOPT (primary)** - already installed, MIT, 10.5 M downloads/month; the foreground service takes a foreground-service option, the JS callback lives in a top-level task definition (a real footgun), `deferredUpdates*` apply **only in the background**, `getMotionActivityAsync()` gives automotive detection with confidence and needs no location permission, and the config plugin adds `FOREGROUND_SERVICE_LOCATION` with a 96x96 all-white PNG icon. **traccar-client-sdk ADOPT-AS-PATTERN** (do not take the dependency: one maintainer, 1,868 downloads/month, young) - **transistorsoft WATCH -> migrate off** (paid release licence, 2,457 open issues) - **react-native-background-actions ADOPT for the voice foreground service only** (4.x requires targetSdk >= 34, matching our Android API 34 requirement exactly) - **expo-battery ADOPT immediately**.

## Decisions

- **ADOPT** Maestro as the single mobile E2E tool **plus** its `assertScreenshot` for the design gate (pin the `cli-2.11.0` release) - `microsoft/playwright@1.64.1` for web E2E and the Lighthouse job - `reg-viz/reg-cli` for self-hosted image diff (no screenshot ever leaves our CI) - `stryker-js` v10.0.0 and `mutmut` 3.8.0 (locked by CONSTRAINTS.md) - `expo@58.0.16` + `expo-updates@58.0.17` + `@expo/fingerprint@0.21.5` with **two channels only** (`production`, `preview`), signed updates, a documented rollback and a runtime kill-switch - `expo/eas-cli@25.2.0` - `sentry-react-native@8.31.0` (DSN only, no auth token in the client) - **GlitchTip** as the error backend (the canonical source is GitLab, the GitHub repo is a 23 KB mirror) - self-hosted **PostHog** (privacy-safe events, no PII) - self-hosted **Langfuse** for the voice/LLM path - **OpenTelemetry** (`@opentelemetry/api@1.9.1`, `sdk-trace-base@2.12.0`) + `opentelemetry-collector` v0.163.0 - the supply-chain chain `anchore/syft@1.55.0` -> `anchore/grype@0.121.0` -> `sigstore/cosign@3.1.3` -> `ossf/scorecard@5.6.0` -> `google-github-actions/auth@v3` (OIDC) - `renovatebot/renovate` 44.171.3 (CI-only, so its AGPL is fine here, but it must be recorded).
- **Auth: KEEP Better Auth** (MIT) with the `organization` + `expo` + `jwt`/`jwks` plugin set, ES256 + JWKS, rate limits, secure cookies and a resource-server-only API that verifies tokens with **zero shared secrets**. Work items: complete the 1.7 migration checklist (async `expo-secure-store` for `expoClient`; re-check `trustedOrigins` for the `courier://` scheme because host-bearing entries are no longer safe; keep `session.cookieCache` and `advanced.trustedProxyHeaders` off; branch on `enableTwoFactor`'s new `method` field) - add **OSV to CI as a blocking gate** and re-check every Better Auth package monthly - write the four missing regression tests that map to real advisories (organisation invitation with an unverified e-mail; rate-limit behaviour under IPv6 prefix rotation; stale sessions after user deletion; `trustedOrigins` rejection of a host-bearing `courier://` entry) - use casbin-style policy modelling for org/team scoping in one policy artefact - record every package and its licence in `docs/product/LICENSES.md`.
- **Location: ADOPT `expo-location` + `expo-task-manager` as the primary** (foreground service, `deferredUpdates*` duty cycling, `activities.automotive` gating) and **`expo-battery` today** for telemetry. **Do not adopt a paid location SDK** - `expo-location` already gives automotive detection with confidence, and our own accelerometer heuristic can refine it inside `packages/`. **Adopt the design of `traccar-client-sdk`** (stationary heartbeat filter, distance filter, activity sampling only at start/resume) inside our own `LocationService` interface. **Keep** `react-native-background-actions` for the voice foreground service, not for location. **Reimplement** the battery-optimisation whitelist intent in our own Android module (the upstream package has **no licence**). Keep transistorsoft only as a benchmarked fallback, with a cost line in `COST_PLAN.md` and an ADR. **KEEP** `fastlane` 2.241.1 and `wataru-maeda/react-native-boilerplate`.
- **WATCH** `devicelab-dev/maestro-runner` - `callstack/agent-device` and `alumnium-hq/alumnium` (a **new 2026 category**: mobile verification driven by AI agents - our QA role could use these) - `sherlo-io/sherlo` - `argos-ci/argos` (after the advisory is confirmed fixed) - the OTel backends (`openllmetry`, `pydantic/logfire`, `SigNoz`, `hyperdx`) - `expo/custom-expo-updates-server` (stale) - `ory/kratos` - `logto-io/logto` - `casdoor/casdoor` - `casbin/node-casbin` - `MasterKale/SimpleWebAuthn` - `1Password/passkey-rs` - `panva/jose` - `lucia-auth/lucia` (only to confirm it stays deprecated).
- **REJECT** `lost-pixel/lost-pixel` (archived) - `tajo/ladle` (no commits in 90 days) - `mutpy/mutpy` (2019) - `wix/Detox` (0 commits in the default branch in 90 days) - `appium/appium` (heavier than we need) - `grafana/grafana` (2 GB, AGPL, OTel-native alternatives exist) - `clerk/javascript` and `workos/workos-node` (hosted dependency) - `supabase/auth` - `nextjs/next.js` and NextAuth/Auth.js (Next.js-specific) - `react-native-keychain` (we already have `expo-secure-store`). **CLEAN-ROOM (behaviour only, never code)** `zitadel/zitadel` (AGPL-3.0) and `traccar/traccar` (AGPL-3.0 - adopt the *client* SDK's design, never the server). **ADR trigger** adopting a hosted service (EAS Update, PostHog Cloud, Sentry Cloud, Sherlo, Argos) as a **production data path for driver data** changes a locked privacy decision - ADR + `docs/decisions/DECISIONS.md`. Nothing in this research recommends one.
